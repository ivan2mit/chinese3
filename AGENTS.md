# AGENTS.md — olympiad-design

Макет платформы олимпиад «Центра социальных компетенций» (ЦСК, доп. образование «Сириус»). Сейчас сделана сторона участника; следующая задача — сторона педагога. Отвечать по-русски, кратко.

## Продукт и ограничения
- Первая олимпиада — китайский язык. Бэкенд — Moodle (своего не пишем). Личного кабинета участника, скорее всего, не будет: вход по коду, выбор теста на главной.
- Приоритет — десктоп, мобильная версия «тонкая» (часть скрывать, часть подписывать мельче). Светлая и тёмная тема обязательны.
- Любое задание должно помещаться в единое окно вопроса без прокрутки страницы (`.q-body` прокручивается только как запасной вариант).
- Педагог при создании задания выбирает оформление (колонки, пропорции картинки, режимы и т. д.). Сейчас эти настройки живут в блоке «Оформление задания» справа в окне теста, это прообраз педагогической стороны.

## Бренд
Золото `#E6A046`, тёмно-синий `#1B2455`/`#000a52`, красный `#AA4E31`, зелёный `#46806A`, сланцевый `#436986`, шампань `#F1EBDA`. Фирменный паттерн: вогнутые ромбы со звёздами и точками (функция `pattern()`), логотип-перо. Шрифты: Montserrat (интерфейс), Noto Sans SC (иероглифы). Все цвета — токены в `:root` (`--gold`, `--solid`, `--sand`, `--line`, `--m0…m4` и др.), тёмная тема переопределяет их; новый интерфейс строить на этих токенах.

## Файлы
- `olympiad.html` — весь макет в одном файле (HTML + CSS + JS, без сборки). `index.html` — его копия для GitHub Pages: после правок `cp olympiad.html index.html`.
- `hz/` — задания по иероглифам (`hz-strokes`, `hz-keys`, `hz-order`): `hz.js` — плеер, собранный esbuild из `../иероглифы/animcjk-task-editor/exercises/olympiad-bridge.js`; `hz.css`; `hzq.json`. `python3 build-hz.py` встраивает или обновляет эти блоки в `olympiad.html` (маркеры `hz:css`, `hz:js`). Исходник плеера принадлежит соседнему проекту; одну правку я туда уже вносил (`renderStrokes`: две независимые стрелки для черт и номеров).
- `backups/` — снимки перед правками (не публикуется, в `.gitignore`).
- Опубликованная копия: https://claude.ai/artifact/JfimhX8oXqD7KXHXqNKBzK (приватный артефакт; перед публикацией нового файла по этому адресу его надо сначала прочитать через `Artifact read`, иначе публикацию отклонят).

## Устройство `olympiad.html`
- Экраны: `go('auth'|'select'|'check'|'test')`; нижняя «пилюля» `.switch` только для набросков. Не забывать, что любой элемент с атрибутом `hidden` должен прятаться (в файле есть `[hidden]{display:none!important}`).
- Окно теста: `.shell` — сетка `176px | 1fr | 300px`, высота `100dvh`. Слева `.qmeta` (номер, тип, «Ответ сохранён»), по центру `.qwin` (`#qBody` + подвал «Назад / Вернуться позже / Далее»), справа `.side` (логотип, тема, таймер, номера вопросов `#nav`, «Оформление задания» `#tune`, «Завершить тест»).
- Состояние: `Q` — массив вопросов (данные); `S` = `{i, ans[], flag[], match[], es[], gp[], pl[], ord[], rc[], hz[], cfg[]}`; `S.cfg[i]` — настройки оформления вопроса. `render()` разветвляется по `q.type`; `chrome()` обновляет навигатор и кнопки; `tune*()` строят панель настроек через `seg(key, options, current)`; клик по `seg` пишет `S.cfg[i][key]` и вызывает `render()`.
- Типы вопросов (индексы в `Q`, с 0): 0–5 один/несколько ответов (текст, картинки, сетка 1–3 колонки, подпись, пропорции), 6–7 сопоставление (линии / банк), 8–10 порядок (список / строка, в том числе картинки), 11–12 размещение на картинке (точки / зоны-многоугольники / скрытые зоны; «переносить» или «тянуть линии»), 13–15 заполнение пропусков (ввод текста с авторасширением / плашки из банка / картинки), 16–17 развёрнутый ответ (текст и/или до 3 картинок, лимит знаков), 18–19 аудио в вопросе и в ответах, 20–21 запись голоса, 22–27 иероглифы (`hz-*`).
- Ключи `cfg`: `type, cols, qmode, amode, cap, ratio, mv, ov, pm, pi, peek, gm, em, lim, plays, pause, rd, rt, rl`.
- Перетаскивание: свои pointer-движки (плашка идёт за курсором, на её месте «окно» `.ph`, соседи расступаются). HTML5 DnD остался только в банке сопоставления и для файлов.
- Звук: плеер `.aplayer` с лимитом прослушиваний (счётчик на сервере, точки остатка), опциональная пауза, при нехватке ширины полоса скрывается (`narrow`). Запись голоса и экран «Проверка звука»: `MediaRecorder`, шкала громкости, демо-режим без микрофона. Карточка «Проверьте звук и микрофон» стоит на странице выбора теста.
- Узкие экраны: в «Размещении» режим линий отключается и вместо него компактный лоток плашек; номера вопросов в `#nav` прокручиваются к текущему.

## Решения по звуку (для Moodle)
Лимит прослушиваний считает сервер, а не JS; каждая дорожка считается отдельно; ссылки на аудио одноразовые, подписанные, персональные, живут 1–2 минуты; проигрывание из памяти. Полностью защитить звук от записи нельзя, цель — исключить переслушивание. Остальное: таймер, журнал подозрительных событий. Требуется небольшой плагин Moodle (вебсервис выдачи токена и обработчик файла).

## Как работать
- Не делать скриншоты (дорого по токенам). Проверять: `node -e "new Function(script)"` для синтаксиса и headless-Chrome с численными замерами (размеры элементов, состояния) через `--dump-dom` и атрибут на `<html>`; `getUserMedia` в headless зависает, использовать демо-режим.
- Перед правкой делать копию в `backups/`; правки вносить Python-скриптом с точной заменой строк и проверять, что фрагмент найден ровно один раз.
- После правки публиковать артефакт по тому же адресу и копировать в `index.html`.
- Известные ловушки: вложенные `<button>` недопустимы (парсер ломает разметку; кнопка плеера внутри варианта — `<span role="button">`); класс `.opt` использует и плеер иероглифов (`hz-keys`), обработчик выбора в `render` защищён условием `Q[S.i].a`; без `<meta charset>` локальный файл показывает кракозябры; микрофон не работает в предпросмотре Claude, только на localhost/HTTPS.
